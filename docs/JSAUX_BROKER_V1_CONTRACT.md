# JSAUX Broker v1.0 — shared implementation contract

Date: 2026-10-18. Document revision: 4 (wire v1.0).
Revision 4 implements Alyenax's request to make 15-game synchronous collections
usable before further write-economy work. It preserves the opaque GIF profile,
192 KiB file limit and single-owner transaction protections. It extends the
advertised coordinated-start budget to 15 seconds and replaces the ten-minute
screensaver allowance with a five-second continuity guard. No per-page USB
uploads or preloaded GIF bank are implied. This specification is not physical
device acceptance. Revision 3 clients must update; the new DAS client can still
use revision 3 servers with the original 2.5-second budget.

Authoritative working copy: this file in the GabeCubeAura separation branch.
Decky-Animated-Screensaver must reference the same document and, when coding
starts, pin its Git revision and SHA-256. Do not maintain independent variants.
Changes to wire behaviour require an updated version and agreement on both sides.
MUST and MUST NOT are requirements; SHOULD is a recommendation requiring an
explicit documented reason if not followed.

## 1. Scope and ownership

- Decky-Animated-Screensaver (DAS) owns the library, SteamGridDB access, cropping,
  GIF preparation, TV installation, player relay and all screensaver settings.
- GabeCubeAura (GCA) owns the broker, device discovery, serial transactions,
  display arbitration, flash admission and return to its current route.
- DAS MUST NOT open a serial device, send USB commands, change global brightness
  or fall back to an autonomous hardware driver. GCA is required for JSAUX v1;
  DAS remains independent for TV-only operation.
- GCA imports no DAS library, API key, media compiler, Studio UI or player manager.
  The broker is a component of the existing plugin, not an additional daemon.
- Screen Sync stays independent: a GCA toggle in Screen Sync activates the LED
  bar during any Steam screensaver. It is not JSAUX consent and is not required
  for matrix delegation. Normal Dashboard/Weather/Artwork/Assistant remain intact.

## 2. Local endpoint and trust boundary

Reference Linux endpoint: `/run/decky/jsaux-broker/v1/control.sock`.
The parent is owned by the Decky backend service identity and mode 0700; socket
and backend-only credential are mode 0600. The trusted installer/backend may
select an alternative absolute runtime directory, consistently on both sides;
frontend requests cannot override paths. Reject symlinked or foreign-owned
endpoint/credential/lock files; never unlink a live or foreign socket on startup.

Use Unix stream sockets with peer credentials checked against the configured
Decky backend identity, plus a random 256-bit capability from a backend-only
credential file. Rotate it on broker restart. It MUST NOT appear in frontend
state, player exports, diagnostics, logs or exported backups. No TCP listener.

This authenticates a trusted local backend, NOT a sandboxed plugin identity:
plugins may share an UID or root. v1 does not defend against a malicious backend
already able to read that identity's private files. Wrong credentials are denied;
never weaken permissions or run privilege escalation to make connection succeed.
The actual service identities and provisioning MUST pass the target-machine gate.

The credential file contains `protocol`, `major`, `boot_id`, `socket_path` and
`capability`; its contents are backend-only. A socket connection starts with
`hello`, carrying the capability. Successful hello creates a random `connection_id`;
subsequent messages on that connection do not repeat the secret. Reconnect needs
a fresh hello. `hello.args` contains exactly `capability`, `client_instance_id`
(random UUID generated by the DAS backend at startup), and `supported_versions`
(maximum four `major.minor` strings). Leases belong to that authenticated client
instance, not its PID or connection. Reconnect of the same live instance can
query/renew its own lease; a restarted DAS instance cannot inherit it. At most
four resident client instances are retained globally. Run cleanup before each
hello and at most once per second while active: an instance becomes removable
after 10 seconds with no connection, no lease, no validation/upload or unfinished
hardware/restoration operation. An active lease expires by the ordinary 8-second
rule first; cleanup cannot release a serial lock or resurrect an operation.
An optional `goodbye` with empty args closes the connection; it neither releases
a lease nor cancels a commit. DAS should release its lease before goodbye.
Reject a fifth non-removable instance with `RATE_LIMITED`, including its earliest
known retry delay; never evict a live lease to make room.

## 3. Framing, envelope and replay rules

UTF-8 JSON objects, one per newline, maximum 65,536 bytes INCLUDING newline.
Reject duplicate JSON keys, nonfinite numbers, nesting deeper than 8, unknown
operations and unknown request fields. No compression, arbitrary paths, URLs,
shell commands, file descriptors or binary deserialization. Process one request
at a time per connection; a disconnected caller may query an accepted operation
after re-authentication. Never keep the socket loop blocked on USB or decoding.

Request:

```json
{"protocol":"jsaux-broker","version":"1.0","request_id":"req-001","boot_id":"broker-boot","op":"goodbye","args":{}}
```

Response (success means RPC acceptance, NOT physical display):

```json
{"protocol":"jsaux-broker","version":"1.0","request_id":"req-001","boot_id":"broker-boot","ok":true,"result":{"closed":true}}
```

Failure:

```json
{"protocol":"jsaux-broker","version":"1.0","request_id":"req-002","boot_id":"broker-boot","ok":false,"error":{"code":"FLASH_DEFERRED","retry_after_ms":30000}}
```

`hello` alone omits request `boot_id`; it negotiates supported major/minor and
returns the current boot ID, connection ID, capabilities, limits and state.
Major mismatch is fatal. Minor additions require negotiation; v1.0 requests use
only fields defined here. IDs are opaque ASCII `[A-Za-z0-9_-]{1,80}`; digests are
64 lowercase hex characters; integers are bounded to JSON safe integers.

Retain up to 256 request receipts per client for 10 minutes, under a global
1,024-receipt LRU bound independent of the four resident instances. Instance cleanup
does not erase the current Steam activation fence or flash history. Receipt LRU
eviction does not authorize a new transfer, and cleaned-up clients cannot inherit
an old lease by recreating their UUID.
Same request ID + identical operation/arguments returns the original receipt
without side effects. Same ID + different arguments returns `REQUEST_CONFLICT`.
An evicted receipt is NOT permission to repeat a write: display activation and
terminal-session fences below independently prohibit a second attempt. An old
boot ID always returns `STALE_BOOT`, even if its request ID was once accepted.

The successful goodbye result is exactly `{"closed":true}`, sent before closing
the connection; loss of that reply has no effect on lease expiry or restoration.

Limits: 2 simultaneous client connections, 20 requests/second/client (burst 40),
5-second idle read timeout, 2-second ordinary RPC deadline, 1-second hello target.
RPC timeout is not cancellation and never grants serial ownership. DAS reconnects
with bounded backoff (1, 2, 4, then 10 seconds); no busy-loop discovery or /proc scan.

## 4. Shared physical ownership

GCA acquires a stable nonblocking interprocess ownership lock per validated
physical device for its ownership lifetime, separate from the serial descriptor.
Use a canonical device key shared across aliases/reconnects when USB identity
permits; do not assume CH340 VID/PID alone uniquely identifies a panel.
Also retain the existing nonblocking `flock` on the actual tty for every transfer.

Only GCA writes in v1, but the common ownership contract must also protect a
future cooperative owner. No lock stealing, PID killing or force option. Loss of
ownership stops admission. A noncooperative third party remains a possible
conflict: fail closed on detected conflict; do not claim absolute exclusion.
Holding the ownership lock does not require keeping the serial port open.

The display lease is separate: it reserves a route so Dashboard refreshes cannot
replace an autonomous collection between transactions. Lock acquisition and all
queue mutations must use one documented lock order; never await a client while
holding a coordinator/serial lock.

## 5. Content registration (no hardware effects)

`register_content` arguments: `sha256`, `size_bytes`, `collection_id` (digest of
the prepared collection specification). Returns existing `content_id` if already
validated, otherwise `upload_id`, `next_offset=0`, and content limits.

`content_chunk`: `upload_id`, `offset`, `data_base64`. Maximum decoded chunk
24,576 bytes. Strict base64; sequential offsets only. Duplicate receipt is safe;
a different overlapping chunk is rejected. Transfer is streamed into private
bounded storage, never accumulated as an unbounded JSON/string buffer.

`commit_content`: `upload_id`. Returns `validation_id`; `operation_status` with
that ID reports `validating`, then `ready` with immutable `content_id` and metadata,
or `rejected`. No USB operation occurs during registration or validation.

`abort_content`: `upload_id`, idempotent. Incomplete uploads expire after 60
seconds without progress. A new boot invalidates upload and validation IDs; a
completed immutable content ID can be rediscovered by `register_content`.

Initial admission profile (software safeguards, NOT measured firmware capacity):

| Limit | v1.0 value |
|---|---:|
| Canvas | exactly 64 × 54 |
| GIF bytes | 196,608 (192 KiB, retained below the observed 200 KiB live/buffer separation) |
| Frames | 6,000 |
| Pages in prepared specification | 120 (DAS responsibility) |
| Total loop duration | 24,000 seconds maximum |
| Frame delays | 1–65,535 centiseconds, explicit on every frame |
| Stored completed contents | 4, maximum 786,432 content bytes |
| Incomplete uploads | 1 globally, maximum 196,608 bytes |
| Total content + staging bytes | 1 MiB; bounded metadata excluded |
| Minimum free disk before admission | 64 MiB |
| Validator | isolated, no network, 64 MiB memory, 5 s CPU / 10 s wall time |

`hello` advertises the effective limits, which may be more restrictive but never
silently more permissive. Lowering limits must not delete active content. If no
inactive LRU entry is removable, reject admission with `CACHE_FULL`; never evict
a registered active lease or partially overwrite a committed file.

Transport profile `gca-collection-rgb332-opaque-v1` intentionally matches the
existing collection encoder, not every legal GIF:

- GIF89a only; global 256-entry RGB332 palette exactly matching `PALETTE_332`;
  no local palettes, transparency, interlace, subrectangles or compositing variants.
- Every image is a full opaque 64 × 54 frame at (0,0). For multi-frame contents,
  every frame has GCE packed byte 0x04 (disposal=1, no transparency/user input),
  valid explicit delay and transparent-index byte zero as emitted by the encoder.
- Exactly one `NETSCAPE2.0` infinite-loop extension precedes multi-frame contents;
  no ANIMEXTS, other application, plain-text or comment extensions.
- Match encoder LZW minimum size 8; validate termination, indexes, exact decoded
  count of 3,456 pixels/frame, subblocks, final trailer and no trailing payload.
- Single-frame output from the current encoder has neither GCE nor loop extension;
  admit as static with no inferred timed-loop or sync-start capability. The delay
  and loop-duration limits apply to timed multi-frame contents only.

Decode streaming with bounded frame state, not all frames in memory. Unsupported
profiles return `CONTENT_PROFILE_UNSUPPORTED`, not a claim of malformed GIF.
DAS must produce this profile before registration; GCA rejects rather than
re-encodes. SHA-256 is checked against the actual immutable bytes, not client claims.
The existing 80-frame rotate helper is NOT a collection validator.

## 6. Operations, Steam activation and leases

`status` has no arguments or USB side effects; uses cached metadata. It returns
hardware/policy state, current boot and Steam activation metadata, optional owned
lease, and safe operation summaries. It never reports secrets or file paths.

GCA obtains actual Steam state through its own existing frontend observer, not
through DAS or the installed player. A positive observation must be at most
5,000 ms old. Track a GCA `activation_id` for each confirmed inactive→active edge.
After observer loss, suspend or restart, invalidate it; require a fresh inactive
baseline then an active edge before granting a NEW lease. This deliberately
prefers TV-only recovery to reviving a stale screensaver session after a crash.
The next real activation can resume ordinary delegation.

`acquire_display` arguments:
`activation_id`, `session_id` (DAS random ID for this player activation),
`content_id`, `collection_id`, `mode` (`sync` or `async`). GCA checks boot,
fresh active Steam state, validated immutable content and all current policies.
One lease globally. Return `lease_id`, `generation`, `operation_id`, relative
`expires_in_ms=8000`, and `alignment_attempt_id` for sync. Acquisition only pins
content and reserves the route: transfer stays `not-started`. It MUST NOT enqueue
USB work until one valid `player_ready` commits the start gate. No second serial
path is opened. This two-step order applies to sync and async modes.

`renew_display` arguments: `lease_id`, `generation`, `sequence` (strictly
increasing, starting at 1). DAS renews every 2,000 ms while its installed player
is active. GCA verifies its independent Steam state on each renewal, using its
monotonic clock. Duplicate/out-of-order renewal never extends the lease. Successful
renewal resets eight seconds; it does not queue, retry or restart any upload.

`operation_status`: exactly one of `operation_id` or `validation_id`.
For display it includes `lease_state`, `transfer_state`, `alignment_state`,
`restore_state`, `reason`, optional `retry_after_ms`, and relative event ages.
DAS may poll at 500 ms while a transfer/alignment is pending, then every 2 s or
use renew receipts. TV playback never depends on an open broker connection.

`release_display`: `lease_id`, `generation`, `reason` from `player-ended`,
`tv-timeout`, `user-disabled`, `client-stopping`. Idempotent; immediately invalidates
pending work and returns `release-pending` if a transaction must finish safely.
`released` is reported only after no old transaction can overwrite a newer route.
`released` does NOT imply that the restoration image is already confirmed.

On Steam inactive, disabled/off policy, priority preemption, USB loss, suspend,
lease expiry or broker stop: revoke without waiting for DAS, fence this activation,
cancel at existing safe worker boundaries, then reconcile the current GCA route
if allowed. Never interrupt a serial commit by starting a competing write.
Late completion can update its receipt, but cannot reclaim the route.

A terminal activation is fenced until GCA observes a genuine subsequent Steam
inactive→active edge. Neither a new DAS session/request ID, reconnect nor renew
can bypass this. Keep only the current activation plus 64 recent terminal receipts;
unknown old IDs are refused, never treated as new. No automatic Assistant→DAS
reupload in the same activation. Registration before activation is permitted;
hardware display from software preview is not.

## 7. States and flash policy

Independent state axes avoid pretending USB completion means optical display:

| Axis | Values |
|---|---|
| lease | pending, active, revoking, released, expired, preempted, rejected |
| transfer | not-started, deferred, queued, transferring, confirmed, unconfirmed, failed, cancelled |
| alignment | not-requested, waiting, candidate, software-coordinated, unconfirmed, abandoned |
| restore | not-needed, pending, deferred, confirmed, unconfirmed, blocked |

`confirmed` means the matching protocol ACK was received. Panel visibility and
phase remain `unknown` unless separately measured. Never expose `sync-success`
based solely on ACK or a cached CRC match. A timely fresh ACK may qualify for a
software-coordinated experimental start without proving optical phase zero.
CRC reuse without a confirmed playback-start action cannot qualify for that
candidate: report `unconfirmed` and continue TV-only in sync mode. No additional
write or undocumented restart command is allowed just to create a candidate.

One acquisition causes at most one admitted upload attempt. All writes/reuse,
including restore, use GCA's CURRENT global flash admission, deduplication and
journal. The screensaver continuity guard is five seconds; do not
reset it on RPC reconnect/new session. Legacy remaining cooldowns are capped
at five seconds on migration. No independent DAS counters, force flag,
per-page upload or heartbeat write. Deferred admission remains deferred until a
new explicit activation; UI may show retry time but must not auto-reacquire in the
same activation. Missing ACK is `unconfirmed`, fences the attempt and MUST NOT
cause automatic resend. Ordinary restoration follows existing protections and
can be deferred. Do not change brightness, Home/in-game preferences or native clock
configuration to fulfil a delegated request.

## 8. Bounded TV start and honest alignment

Three outcomes are distinct: software-coordinated experimental start, physically
measured alignment, and abandoned attempt/TV-only. v1 permits the FIRST as the
meaning of the mode, labelled "Synchronised (experimental)" with concise help
"Coordinated start; exact visual synchronisation is not guaranteed". Physical
alignment is always `unknown` in v1. It is not a prerequisite for experimental
use. A bounded software candidate is not itself a measurement of phase zero.

Maximum sync wait: 15,000 ms from player readiness, not acquisition or
broker receipt. Use ONE absolute `deadline_mono_ms`, never receipt-time + wait.
The installed export fixes `sync_wait_ms` at 15,000 for revision 4 or 2,500 for
revision 3. It cannot be extended after readiness. TV starts as soon as its
timely candidate arrives, not at the end of the full budget. The acquisition
remains free of USB writes. Receipts, cancellation, renewal and Steam-inactive
revocation continue during this longer bounded wait.
DAS backend and broker must use the same host Linux CLOCK_MONOTONIC domain
(floor(monotonic_ns/1,000,000), safe JSON integer). No wall-clock timestamps.

The browser has a different time origin. DAS maps its ready event conservatively
before requesting USB work, using three backend relay clock samples: for browser
send/receive `p_send,p_recv` and backend sample `b`, host-minus-browser offset is
in [b-p_recv,b-p_send]. Intersect the intervals; require width <= 50 ms, samples
<= 30 s old, no visibility/suspend/time-origin discontinuity. Let
`ready_mono_ms=floor(p_ready+offset_lower)` and deadline=ready_mono_ms+sync_wait_ms. The
conservative deadline is never later than the actual ready+sync_wait_ms bound. Native
player also enforces its own local ready+sync_wait_ms watchdog; it cannot extend that
watchdog because relay/broker replies arrive late. Invalid clock mapping means
TV-only sync, not a guessed deadline. Async needs no browser clock mapping.

Order: register content beforehand -> authenticated installed relay/session and
collection match -> acquire lease without USB -> ready event -> `player_ready`
with immutable start gate -> at most one worker attempt -> timely candidate or
timeout -> start TV -> `tv_started`. No acquisition/ready retry can reset a gate.
GCA rejects a gate already expired or ready in the future, and any ready/deadline
span outside 2,500..15,000 ms. DAS verifies its exact installed-export span.
It checks the same deadline before enqueue, before serial start and before each
existing safe cancellation boundary. An in-flight commit may still complete;
this limitation must not be hidden by labelling it cancelled before it is safe.

An ACK candidate that arrives before the broker deadline is still unusable if DAS
or the player receives it after that SAME deadline. A timely candidate starts TV
once and reports `software-coordinated`; no candidate by deadline starts TV alone
and abandons the sync lease. Candidate creation requires a fresh matching ACK for
this operation, with `phase_basis=gif-end-ack-assumption`; optical phase is unknown.
Async can retain a valid lease after TV starts, without coordinated-start claims.

At deadline, GCA revokes any sync attempt without a timely `tv_started` committing
the timely candidate, independently of renewals or a missing release. A delayed
`tv_started` may therefore report TV started while delegation was revoked; TV
continues and status must reflect loss of matrix authority, never silently reacquire.
`player_ready` and `tv_started` never extend a deadline or requeue hardware.
Reject late ACK as alignment evidence; preserve it only as a transfer receipt.
A transfer already committed may briefly show old content before normal restore;
do not promise atomic cancellation or instant restoration that firmware cannot give.
Do not retry/restart a GIF to catch up, nor block TV beyond its deadline.

### Exact start-gate operations

Both use the ordinary authenticated envelope, boot ID and request replay rules.
The server verifies that lease, session and operation belong to this client.

`player_ready.args` contains exactly:
`lease_id`, `generation`, `alignment_attempt_id` (null for async),
`ready_mono_ms` (null for async), `deadline_mono_ms` (null for async),
`clock_uncertainty_ms` (integer 0..50 for sync, null for async).
For sync the deadline MUST equal ready+the fixed installed `sync_wait_ms` and must not exceed the current
Steam activation/generation boundary. The first valid call freezes the gate.
Return `operation_id`, `gate_accepted=true`, `deadline_mono_ms`, `transfer_state`,
`alignment_state`, `remaining_ms` (null for async). Same arguments under a new
request ID return the same gate, without enqueue/extension; changed arguments
return `GATE_CONFLICT`. Fresh Steam state and policies are checked again before
scheduling. Expired gate returns `ALIGNMENT_EXPIRED`; bad mapping returns
`CLOCK_UNAVAILABLE`; wrong IDs return `STALE_GENERATION`/`LEASE_EXPIRED`.

`tv_started.args` contains exactly:
`lease_id`, `generation`, `alignment_attempt_id` (null for async),
`started_mono_ms` (null for async), `outcome` (`software-coordinated`, `tv-only`,
or `independent`), `candidate_id` (null except software-coordinated).
A candidate is a one-use opaque receipt issued by GCA for this operation's ACK
before the fixed deadline and returned by `operation_status`; it includes
`candidate_id`, `deadline_mono_ms`, `phase_basis`, `optical_alignment="unknown"`.
For software-coordinated require start AND receipt of tv_started before deadline,
matching unconsumed candidate and still-active policy/Steam state. The response
is `recorded`, `lease_state`, `alignment_state`, `restore_state`; it never claims
optical proof. `tv-only` immediately revokes sync work; `independent` is async-only.
Duplicate identical outcome has no effects; a conflicting outcome returns
`GATE_CONFLICT`. Late coordinated claims return `ALIGNMENT_EXPIRED`, retain any
late start as diagnostic only and cannot reactivate the lease.

## 9. Errors and UX mapping

| Codes | Behaviour |
|---|---|
| AUTH_DENIED, VERSION_UNSUPPORTED, STALE_BOOT | close/re-negotiate; no USB fallback |
| INVALID_REQUEST, REQUEST_CONFLICT, RATE_LIMITED | bounded client correction/backoff |
| CONTENT_INVALID, HASH_MISMATCH, CONTENT_TOO_LARGE, CONTENT_MISSING | repair/register content; TV unaffected |
| CONTENT_PROFILE_UNSUPPORTED | prepare canonical opaque GIF89a profile; no firmware experiment |
| CACHE_FULL, DISK_LOW, VALIDATION_LIMIT | show local preparation issue; no USB |
| DEVICE_ABSENT, DEVICE_BUSY, OWNERSHIP_UNAVAILABLE | TV only; do not steal ownership |
| FACEPLATE_DISABLED, DISPLAY_OFF, SUSPENDED, PRIORITY_ACTIVE | respect policy; no preference changes |
| STEAM_INACTIVE, STEAM_STATE_STALE, ACTIVATION_CLOSED | refuse/revoke display; no timer-based reacquisition |
| FLASH_DEFERRED, MIN_HOLD | show deferred and retry estimate; no bypass |
| LEASE_CONFLICT, LEASE_EXPIRED, STALE_GENERATION | reject stale client operation; no implicit replacement |
| USB_UNCONFIRMED, USB_FAILED | distinguish missing confirmation from confirmed display |
| ALIGNMENT_EXPIRED | TV continues, no catch-up write |
| CLOCK_UNAVAILABLE, GATE_CONFLICT | reject unsafe/changed start gate; TV-only, no deadline reset |

Non-enumerated internal failures map to `INTERNAL_ERROR` with a bounded diagnostic
ID, not raw tracebacks, serial bytes or filesystem paths. Receipt details are
retained separately from the current user-facing phase. Diagnostics record bounded
state changes/counts/durations and hashed content IDs; never audio, API credentials,
capabilities, full payloads or per-frame logs. GCA exposes broker details under
Advanced/debug; DAS owns its JSAUX card. No new quick-panel shortcut is needed.

First detected panel may configure output + sync in DAS, but MUST NOT issue USB,
change brightness or override a later manual choice. Synced playback disables
shuffle and follows TV duration/order. Failure of the matrix does not block TV
preparation or installation. "TV + JSAUX" must not imply ACK before confirmation.

## 10. Migration and coordinated removal

1. Implement broker and client against this pinned contract with shared fixtures.
2. DAS provides explicit verified import of reusable Studio media/settings; no
   silent key transfer, source deletion or installation takeover.
3. Validate new TV export and broker path before removing GCA's Studio UI/services.
4. Preserve old library/export as recoverable until user-confirmed cleanup. Only
   the owning installer removes its own export; never reuse the other's marker.
5. Put the existing screensaver toggle back in GCA Screen Sync, preserving its
   saved value. Retire only the old Studio-specific relay/RPC after client cutover.

Two preparation roots have separate locks today: do not let migration run both
heavy preparation pipelines concurrently. Migration is explicit, not background
reconversion on upgrade. No dependency on a desktop standalone application.
